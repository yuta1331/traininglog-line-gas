# ADR-0001: `doPost` を薄い adapter にし、メッセージ処理を messageHandler と記録ストアに分ける

- ステータス: Accepted
- 日付: 2026-08-11

## 背景

`doPost` 1つが10個の責務を持っていた ―― HTTPボディのパース、`events` のループ、許可ユーザー判定、自動既読、`json書き出し` コマンドの分岐、シート取得、7列への行マッピング、`LockService`、`setValues`、エラー処理。git 上でも最も変更頻度の高いファイルだった。

これが実害を生んでいた。エラー処理が1つの `catch` に集約されていたため、**シート不在や `setValues` の失敗でもユーザーには「フォーマット間違ってるよ！📝」と返っていた**。ユーザーは自分の入力を直そうとするが、直しても直らない。

## 決定

3つに分ける。

1. **`doPost`** — HTTPの出入りだけ。ボディのパース、`events` の分解、1件ごとのエラー隔離、`{userId, text, markAsReadToken}` への整形、処理結果の文言化と返信、`TextOutput` の生成。
2. **メッセージハンドラ** — テキストメッセージ1通を受け取り、処理結果（判別可能なユニオン）を返す。認可・既読・コマンド判別・保存・書き出しの**順序**を内側に持つ。
3. **記録ストア** — 列順・排他・`setValues`。

依存は第2引数の `deps` オブジェクトで渡す。DIコンテナは入れない。

### 付随して決めたこと

- **`(globalThis as any).doPost = doPost` はエントリファイル（`src/index.ts`）に残す。** ビルド後の `dist/index.js` では、この実行時の代入だけが `doPost` を公開している。gas-webpack-plugin（gas-entry-generator）が検出するのは `global.x = ...` の形だけで（`node_modules/gas-entry-generator/index.js:182`）、`globalThis` への代入からはトップレベルのスタブが生成されないため、代替経路が存在しない。この改修ではビルド出力の形状を master と同一に保つことを制約とし、`global` への書き換えでプラグインを働かせる選択肢は採らなかった。
- **`LockService` は記録ストアの内側に置き、`getLastRow`+`setValues` だけを囲む。** ネットワークI/Oを排他に含めると全 Webhook 処理が直列化する。
- **許可ユーザーの読み込みは `doPost` でリクエストあたり1回。** 判定と順序制約はハンドラ内だが、ロードを1件ごとに行うと複数イベントのバッチで UserList シートを N 回読むことになる。
- **イベント処理が失敗しても常に 200 を返す。** LINE の再送は Webhook 配信全体を再送するため、非2xx を返すと成功済みイベントが再処理され、重複排除を持たない現状では行が二重化する。
- **処理結果は文言を含まない。** 文言化は `doPost` 側の関数が担い、処理結果と文言の N:1 対応を許す。テストが絵文字入りの文言に縛られないため。

## 採らなかった選択肢

- **ハンドラにリクエストボディ全体を渡す** — `doPost` は最も薄くなるが、ハンドラが LINE の Webhook ペイロード形式を知ることになり、分離の動機が半分死ぬ。
- **コマンド分岐を `doPost` 側に置く** — 「認可 → 既読 → 分岐」の順序制約が再び2箇所に散る。
- **記録ストアをハンドラの内部実装として抱える** — `export.ts` が既に同じシートを読んでおり利用者が2つある。ストアを差し替えられないとハンドラのテストが常に本物のスプレッドシートを要求する。
- **`now` を `deps` に入れる** — 現在時刻依存は `parseTrainingLog` の内部事情。テストは `vi.setSystemTime` で足りる。

## 結果

- シート障害とフォーマットエラーが別の文言になった
- 内部の英語エラーメッセージがユーザーに露出しなくなった。代償として `Logger.log` が唯一の手がかりになるため、保存失敗・想定外エラー・混雑の全経路で元例外を記録することを必須とする
- ハンドラが GAS 非依存になり、vitest でテストできるようになった
